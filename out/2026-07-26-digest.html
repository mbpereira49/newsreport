Ruff’s big default-rule jump broke the quiet contract of dev dependencies

The Python linter now enables 413 rules by default, up from 59 — a reminder that unpinned tooling is still production risk.

Astral’s Ruff v0.16.0 shipped July 23 with a much larger default rule set: 413 enabled rules, up from 59. Simon Willison noticed the practical consequence when CI jobs began failing because his development dependency on “ruff” was unpinned. The release expands defaults after years of rule growth, from 708 rules in v0.1.0-era context to 968 now, including checks that can catch syntax errors and immediate runtime errors.

Why it matters: Better defaults can still be breaking changes in practice. For teams, this is a small but useful parable: pin your developer tools, especially when they sit in CI and can stop work across multiple projects overnight.
